# 能力深度分级

能力分级用于判断对某项技术掌握到什么程度，不绑定某一个项目。

| 层级 | 判断标准 |
|---|---|
| L0 识别 | 知道技术名称、用途和所在系统层 |
| L1 使用 | 能依照可靠例程完成接线、配置和运行 |
| L2 理解 | 能解释原理、时序、关键参数和代码路径 |
| L3 独立实现 | 能依据数据手册完成新器件或新功能接入 |
| L4 系统整合 | 能组合硬件、驱动、协议与应用，处理异常 |
| L5 工程化 | 能优化功耗、可靠性、成本、升级和批量部署 |
| L6 深入研究 | 能分析底层机制、修改核心实现或设计新方案 |

## 评估维度

同一技术分别观察：

- 原理理解
- 硬件接入
- 软件实现
- 调试定位
- 系统整合
- 工程交付

## 应用案例的作用

横向应用案例用来暴露知识缺口。例如 NFC 水墨屏同时涉及：

- NFC 通信
- 电子纸驱动
- MCU 或 SoC
- 图像数据处理
- 供电与功耗
- 分包、校验和异常恢复

完成案例并不代表整个嵌入式体系已经掌握，只能证明相关能力在该场景中达到一定层级。

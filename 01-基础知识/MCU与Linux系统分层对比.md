# MCU与Linux系统分层对比

## MCU典型结构

```text
业务逻辑
→ HAL/驱动
→ 外设寄存器
→ 硬件
```

程序通常拥有较高硬件权限，应用、驱动和系统边界较弱。

## Linux典型结构

```text
用户态应用
→ 系统调用/设备文件
→ 内核子系统
→ 设备驱动
→ 硬件
```

用户态程序通常不能直接随意访问物理寄存器。内核负责进程、虚拟内存、文件系统、网络和驱动。

## 关键对应

| MCU | Linux |
|---|---|
| main循环或RTOS任务 | 进程与线程 |
| HAL驱动 | 内核设备驱动 |
| 中断服务程序 | 内核中断处理 |
| 固件整体烧录 | Kernel、设备树、RootFS和应用分别部署 |
| 直接寄存器访问 | 通过驱动和系统调用访问 |

## 对Unity开发的意义

Unity部署到RK/Android时仍是用户态应用。需要硬件能力时，通常通过系统API、Native插件、服务或设备驱动连接，而不是直接复制STM32寄存器代码。

## 协同模式

RK适合UI、联网、媒体和AI；MCU适合电机、采样和实时控制。双方通过UART、USB、CAN、SPI或网络交换命令和状态。

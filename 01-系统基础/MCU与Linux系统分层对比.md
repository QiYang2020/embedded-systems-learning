# MCU与Linux系统分层对比

## MCU典型结构

```text
业务逻辑
→ HAL/驱动
→ 外设寄存器
→ 硬件
```

程序通常拥有较高硬件权限，应用、驱动和系统边界较弱。

## Linux典型结构

```text
用户态程序
→ 系统调用/设备文件
→ 内核子系统
→ 设备驱动
→ 硬件
```

用户态程序通常不能直接随意访问物理寄存器。内核负责进程、虚拟内存、文件系统、网络和驱动。

## 关键对应

| MCU | Linux |
|---|---|
| main循环或RTOS任务 | 进程与线程 |
| HAL驱动 | 内核设备驱动 |
| 中断服务程序 | 内核中断处理 |
| 固件整体烧录 | Kernel、设备树、RootFS和应用分别部署 |
| 直接寄存器访问 | 通过驱动和系统调用访问 |

## 平台集成意义

在RK/Linux平台上，硬件能力通常通过设备节点、系统API、用户态库或服务暴露；在MCU上，业务逻辑往往直接调用固件驱动。系统集成需要明确功能应放在用户态、驱动层还是MCU侧。

## 协同模式

RK适合界面、联网、媒体和AI；MCU适合电机、采样和实时控制。双方通过UART、USB、CAN、SPI或网络交换命令和状态。

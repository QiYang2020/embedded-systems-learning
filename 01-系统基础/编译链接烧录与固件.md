# 编译、链接、烧录与固件

## 从源码到设备

```text
C/C++源码
→ 预处理
→ 编译为目标文件
→ 链接
→ ELF
→ 转换为BIN/HEX
→ 烧录到Flash
→ CPU执行
```

## 各产物的作用

- 目标文件：已经编译，但地址尚未最终确定。
- ELF：包含机器码、地址、符号和调试信息。
- BIN：连续的纯二进制数据。
- HEX：带地址信息的文本编码格式。
- MAP：展示函数、变量和内存占用位置。

链接脚本决定代码和数据放入哪段Flash或RAM。烧录工具只是把指定映像写入目标存储器，并不会修复错误的地址布局。

## 与普通应用开发的区别

普通PC或手机应用由操作系统加载；MCU固件通常直接位于固定Flash地址，复位后从约定入口启动。

## 建议观察

编译一个STM32空工程，比较ELF、BIN、HEX和MAP文件；修改一个全局数组大小，观察RAM和Flash占用变化。

## 常见误解

- 编译成功不代表能够启动。
- BIN文件小不代表运行时内存占用小。
- “下载”在嵌入式语境中通常指烧录，不是从网络获取。

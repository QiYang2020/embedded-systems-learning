# MCU驱动与Linux驱动的区别

## MCU中的驱动

MCU项目中的驱动通常与固件一起编译，直接调用HAL、LL或寄存器。

```text
业务逻辑
→ 外部器件驱动
→ HAL/LL
→ MCU片上外设
→ 硬件
```

常见形式是C源文件、头文件、初始化函数、读写函数和状态结构。驱动与业务边界由项目自行设计。

## Linux中的驱动

Linux驱动运行在内核空间，并接入Linux设备模型或某个内核子系统。

```text
用户态程序
→ 系统调用、设备节点或系统接口
→ Linux内核子系统
→ 器件驱动
→ SoC控制器驱动
→ 硬件
```

Linux驱动通常涉及：

- 设备树匹配
- probe与remove
- platform、I²C、SPI等总线框架
- 中断、时钟、电源和GPIO资源
- 设备节点、sysfs或专用内核子系统
- 内核模块编译、加载和日志

## 同一器件的差异

以I²C传感器为例：

| MCU | Linux |
|---|---|
| 固件主动初始化I²C控制器 | SoC控制器驱动提供I²C总线 |
| 代码直接写器件地址和寄存器 | 设备树描述器件地址和连接 |
| 驱动函数直接被业务调用 | 驱动接入IIO、input、hwmon等子系统 |
| 与整个固件一起编译 | 可内建内核或编译为模块 |

## 当前参与深度

- MCU外部器件驱动：主要参与，目标是独立实现。
- Linux设备树和简单器件驱动：按需参与，目标是能够适配和修改。
- SoC复杂控制器、GPU、NPU、ISP驱动：以集成、版本管理和问题定位为主。

## 判断“驱动问题”的方法

先确认问题位于哪一层：物理连接、总线控制器、设备树、器件驱动、用户态权限或业务逻辑。不要只因为设备无法工作就直接认定为驱动错误。
